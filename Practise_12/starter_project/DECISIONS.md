# Ключевые решения по проекту (Практическая работа №12)

1. **Отказ от побочных эффектов в Stream API и иммутабельные результаты:**
   Все аналитические методы в `SalesAnalyticsService` строятся как чистые потоки данных без изменения исходного списка `sales` и без наполнения внешних списков через `forEach(list::add)`. Для сборки списков используется терминальный метод `.toList()`, для поиска максимума — `.max(...)` с возвратом `Optional<Sale>`, а для подсчёта выручки по менеджерам — `Collectors.groupingBy` с `Collectors.summingDouble`.

2. **Локализация порога крупной сделки (Вариант 7) в константе `LARGE_SALE_THRESHOLD`:**
   Граница крупной сделки (`LARGE_SALE_THRESHOLD = 40_000.0`) вынесена в одну константу в `SalesAnalyticsService` и используется в методе-предикате `isLargeSale(Sale)`. Благодаря этому классификация сделок (`SaleCategory`) и фильтрация крупных продаж (`largeSales`) не дублируют число `40000`, а изменение порога при проверке выполняется правкой одной строки.
